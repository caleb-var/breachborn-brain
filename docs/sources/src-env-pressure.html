Architecture pressure test — 25 November 2026

User requested a full pressure test before approving the environmental architecture. This record supplements earlier probes; it does not establish a finished stack. Independently written Python/NumPy/SciPy and C++17 probes were executed on virtualized AMD EPYC 9V74, Linux, no target Godot or GPU. GitHub cloning remained blocked by DNS; public upstream source and the canonical Brain were read via connector. No vendor suite, engine build, Godot integration, production save or target GPU benchmark was executed. No engine code changed. Results and exact executable sources/images are supplied in the chat archive breachborn_architecture_pressure_test.zip (41 files; SHA-256 c7878d16c36fe4697b5d66418a66d7090c770fdc04e547fb09e98dd90b97e176). The archive is not checked into this repository; the numerical evidence and limitations are recorded here. Reference targets remain Ryzen 7 3700X, RTX 2070 SUPER, 32 GB, 8x rendered, historical 25 aggregate environment CPU-ms/game-s; 144 physical seconds/game-second is a sensitivity scenario, not accepted universal timing.

Storage, routing and groundwater

Independent analytical fixtures (breachborn_pressure_physics.py):

  • 1km square, 1m wide 1km channel, 2m banks, 1500m3: true stage 1.5m, averaged-bed stage 1.9995m; true wetted area 1000m2 vs 1e6m2. Exact piecewise volume curve preserves shape; averaged terrain fails.
  • Two 1000m2 basins with 1m wall, 800m3 initially upstream: actual stages .8/0m; lumping yields .4/.4m. Add 500m3, simplified free weir C=1.7 width2m, 1s steps: downstream .1m at 242s, after 3600s stages 1.015824/.284176, residual -1.14e-12m3. Splitting a .6m water compartment then removing 200m3 from side A leaves .4/.6m, exact stock. This is a controlled geometry fixture, not a 2D dynamic inundation proof.
  • Linear diffusive-wave IRF reference (mizuRoute method): L=10km, c=2m/s, D=100m2/s, 600s 10m3/s pulse, bins20s. Mean transit5000s, SD500s. Reference peak4.558m3/s; pure delay 10m3/s, L1 114.23%; one gamma reservoir 1.131m3/s, L1 160.46%, early volume47.34% before3500s; 4/16/100 stages L1 127.54/79.61/2.105%. No early delivery via a closed dam; held packets need backwater resolution, not just gate check.
  • Compact shifted-gamma alternative matching mean/variance (breachborn_routing_groundwater.py), D=25/100/400/1600m2/s: shifted 16 stages at D100 delay3000s, L1 4.305%, peak+1.341%; 4 stages D100 L1 15.232%; 16 stages D25/D400 L1 4.567/2.413%; 4 stages D1600 L1 5.117%. This is mathematical screening, not a selected implementation or proof of runtime expense/physical nonlinear routing. Compare actual mizuRoute IRF/kinematic/MC methods; use bounded compressed response only where stage feedback negligible, own transit, refine on edits/high flow.
  • Two linear finite aquifers each storage derivative 1000m2 and conductance2m2/s, tau250s: exact at dt250s heads .68394/.31606m; explicit .5/.5, backward Euler .75/.25 (-20.9% transferred volume). At dt1000s donor-limited explicit exchanges all initial water, overshoots equilibrium; backward Euler still -18.5% transfer. Exact pair update is useful control; general spatial aquifer/stiff heterogeneous network unqualified. Stable or mass-conserving is not sufficiently accurate.

Native surface cost and critical extended failure

breachborn_pressure_bench.cpp: synthetic 100x100km regular grid, two faces/cell, variable beds and sparse crests, piecewise storage V(h), explicit local-inertia face update, donor limits, exact friction power vs lookup. No terrain scans, real curves, topology repair, local SWE, pollution, transfers or renderer. Median thread CPU five batches. Original illustrative dt=.5dx/sqrt(g2m) is NOT adequate for this subgrid geometry; near-dry small negative roundoff volumes reported. Original timings (pow/table ms/step; table normalized at alpha144): 1km .6268/.3824, .4878ms/game-s; 250m 10.7828/6.5535, 33.4407; 100m 53.4406/27.4966, 350.7687.

breachborn_water_table_check.cpp: 100x100 cells at 1km/250m, 500 steps per row (different physical durations with dt changes). At original dt max stage difference 1.264979m/2.104131m; end volume L1 fraction .001153/.92869; both conserve mass. At half dt max difference 1.485e-8/2.582e-8m; quarter and tenth dt also agree to tiny tolerances. This only checks consistency against the same simplified pow method, NOT physical correctness, convergence or sufficient CFL. Geometry/storage derivative and conveyance can make the naive wave-speed timestep unreliable; fix stability law and geometry consistency before benchmarking candidates. No reuse preference for this prototype.

Reduced-dt workload rerun (breachborn_water_reduced_dt_bench.cpp): 1km 10k cells dt56.44046s, .29835 CPU-ms/step -> .76120 CPU-ms/game-s; 250m 160k cells dt14.11011s, 4.49963 ->45.92075; 100m 1M cells dt5.64405s, 29.26409 ->746.63279. All costs are scoped synthetic CPU, not target benchmarks. Broad 250m or 100m fully active solver is not the default at historical alpha144. Test connectivity-aware variable-resolution storage with actual subgrid face geometry; SFINCS paper supports subgrid method, reports 35–50x on particular 100m vs25m applications but unresolved meanders overestimate flux, bins and fine preprocessing cost real. GPL reference only under current policy.

Rapid local water: FluxCell preprint (24 Nov 2026, not peer reviewed) reports 610–700M cell updates/s on integrated laptop GPU; actual project pin c62d8118839831529399b33815bac52a94738f55 MIT, CPU references and editable bed, fixed solid mask; no independently executed vendor code. Illustrative 256x256 1m patch at physical dt=.05s, 8x game speed: alpha1 needs10.486M updates/s, ideal nominal .2865 GPU-ms/frame at published lower rate and60FPS; alpha144 needs1.510B updates/s, 41.26ms/frame, impossible for a 60FPS budget on that throughput. Even 64x64 alpha144 nominal2.58ms/frame. This is arithmetic, not target timings; includes no GPU integration/copies or actual variable dt. Define physical-clock policy before selecting local simulation; no silent clock changes or camera-dependent flow.

Atmosphere and coupled fixture

Prior known-answer tracer: MC at16km retains95.27% broad sigma64km peak, only48.96% sigma12km. New idealized 256km ridge/transport experiment prescribed 2 layers, wind20m/s, uplift/saturation; 16km MC windward/lee rain21.524/4.933mm, 1km MC17.723/6.159mm; local intensity and distribution differ despite mass conservation. This is not dynamic weather.

Native synthetic atmosphere: four float fields, eight layers, varying signed divergence-free horizontal winds, split AVX2 MC transport, prescribed vertical mixing, saturation LUT, condensed and falling rain, surface actual water and latent/sensible exchanges, no pressure/dynamics or true air/land physics. Median combined per-step CPU on EPYC: 32km (125^2*8) 2.837ms at dt533.333s, .766 CPU-ms/game-s alpha144; 16km 9.175ms dt266.667s,4.955; 8km 33.713ms dt133.333s,36.411. Relative float mass residual max7.28e-8, simplified energy residual relative total max2.92e-8. No claim of physical thermal accuracy, pressure speed, timestep validity or engine overhead. 8km global unsuitable as default at scenario clock, 32/16km coarse candidates.

Independent manufactured horizontal pressure test (breachborn_pressure_circulation.py): scipy single-worker periodic constant 5-point Laplacian FFT at side125/250/500 median .1695/.5763/3.3069ms; heterogeneous positive open-area coefficient (minimum near .1) same simple solver relative residual .09468, preconditioned CG correction 19/20/20 iterations,7.942/27.607/138.133 CPU-ms, relative residual below1e-6. Python/scipy timings not optimized native pressure solver; not a true terrain-following 3D atmosphere. Illustrative explicit c=100m/s, dx16km, Courant .5 ->80s instead of266.7s; trapezoidal oscillator phase error -11.45% for wavelength128km at266.7s. c300m/s ->26.67s, -43.99% phase error for128km. No universal dt from wind alone; semi-implicit stability does not guarantee propagation accuracy. Prioritize reduced pressure/wind closure and parameterized uplift with actual causal weather tests; do not port Weather3D wholesale or assume diagnostic wind is sufficient. Compare dry/wet moist shallow-water, reduced hydrostatic and low-cost diagnostic variants; actual circulation remains unresolved.

Independent connected accounting fixture (breachborn_connected_fixture.py): eight 1000m horizontal columns of artificial area10000m2, prescribed two-layer wind/mixing and simplified heat balance, finite surface soil/aquifer and two 100m2 basins, gate opens43200s. Dry case produces no rain. Explicitly cooled humid case at dt20s: 1,006,476.176kg rain,397,331.051kg actual evaporation,1114.457m3 runoff,671,024.420kg recharge; no-evap control625,207.253kg rain (difference381,268.923kg). Protected basin remains dry, hazard crosses at43220s; dt10s crosses43210s and rain1,006,228.840kg (0.0246% difference), end basin stage .308156 vs .308076m. No negative stocks, water and simplified sensible/latent energy ledger close to roundoff with explicit external forcing. Raw pickle bytes differ after restart; canonical arrays/scalars digest exactly equal. Not game persistence, full thermodynamics, real circulation or forecast accuracy. Initial atmospheric water contributes to rain; not all rain is new evaporation. Preserve successful accounting boundary; no solver chosen.

Clouds

Executed standalone CPU real 3D density raymarch (breachborn_cloud_pressure.py, breachborn_cloud_sculpted.py), deliberately sculpted ellipsoid union plus surface detail, 96^3 quantized density/light, directional optical depth precompute, no nested light march, bounding volume and transmittance early-out. 640x360 96-step same-asset reference vs160x90 32-step bilinear upscale. Sculpted below:7,892,748 vs164,520 primary samples,47.97x, cloud-mask sRGB RMSE2.428/255; close18,874,912 vs394,715,47.82x, RMSE1.624; softer inside22,118,400 vs460,800,48x, RMSE .041. Static single smooth volume, mask reference transmittance<.98, no overlapping clouds, GPU, temporal reconstruction, actual terrain composition or art acceptance. Changed sun direction and stale baked lighting yields cloud-mask RMSE46.267/255 sculpted,25.355 softer. Reject fixed directional lighting for day/night. Candidate bounded true 3D density raymarch with live directional light approximation/directional caches, compare existing SunshineClouds2 (not validated), SDF skipping and temporal reconstruction; Nubis cubed method evidence, not performance guarantee. User reference art remains higher quality. Require below/above/inside, multiple formations, storm overcast, changing sun, camera/time motion, correct opaque geometry clipping and GPU timing on target. No CPU software-render time extrapolation to GPU.

Navigation and terrain

breachborn_hpa_pressure.cpp: independently authored HPA-style two-floor256x256 synthetic walk grids with 16x16 clusters, explicit stair portals, sampled entrances, exact local BFS and abstract A, intercluster door as dynamic link. 2912 abstract nodes,19344 directed edges,13.939ms build,243776B raw node-position/edge payload excludes mapping/scratch/capacity. 400 sampled paths: open grid A183.049ms vs hierarchical16.028ms (11.42x), mean stretch2.396%, p95 11.881%, max37.5%; closed214.382 vs15.402ms (13.92x), mean2.486%, same p95/max. No false blocked/false path in sampled cases, not universal reachability proof. Door fixture exact and abstract path8->138; no graph rebuild for this explicitly represented intercluster link. No actual path refinement, 3D terrain, crowd, library, capability-policy or 100k acceptance. Shared macro fields in separate benchmark: 250^2 unweighted graph, 500 fresh A87.524ms, 20 reverse fields6.348ms, 100k cached cost lookups .558ms; cache5,000,000B, 0 mismatches on500 sampled searches. Shared queries promising, lookup is not movement or per-agent planning. [HPA](https://webdocs.cs.ualberta.ca/~jonathan/publications/ai_publications/jogd.pdf) and DHPA/SHPA literature supports qualification; selective caches, no universal cached all-pairs. Door inside a local cluster requires explicit conditional link or local repair. Population/ECS remains unqualified.

Terrain: pinned GeoGenesis author benchmark 1024^2 generation1.82s, approximate .4s/10k-year step, 200 steps ~80s rough extrapolation; tiled4096^2 initial-only3.4–3.8s vs single shot37.5s/3.1GB, not proof of aged fine world. No actual GeoGenesis, PWG or Zylann upstream execution. Retain user terrain soft lock conditional on natural drainage, deterministic seams, latent channel topology, cave/door/structure geometry and offscreen edits without global fine sampling. A render-only generated tributary cannot participate in physical drainage before its connectivity is known. Preserve topology as a compact feature constraint, not as independent fine resident solver state.

Decision status and next qualification

Do not claim full compatibility or lock production implementations. Retain only design-level shared ownership, independent domain scales, user soft-locked terrain, hierarchical navigation direction and true volumetric clouds. Reject blanket fine grids, unqualified native water retention, single reservoir routing, average-elevation storage, global fine atmospheric grid, fixed cloud lighting, all-agent per-frame path search and arbitrary clock compression. Candidate gates:

  1. Freeze common clock policy and response/travel semantics, actual target budgets and accuracy tolerances. At historical alpha144 local visible dynamics and even one detailed patch can exceed budget. Do not solve by silently slowing water or weather, or dropping elapsed time.
  2. Qualify actual GeoGenesis/PWG/Zylann geometry and topology before large integration; compile/run pinned tools on target. Determine whole-world feature counts, curve bytes, dirty edits and conservative promotion/restriction.
  3. Run independent upstream hydraulic CPU controls and target FluxCell GPU; low-Froude connected subgrid vs reference, dry-bed dam, broad storm, backwater, edited dam, coarse/fine seam flux/time/mass, physically meaningful stage/arrival plus inclusive costs; geometry-derived stable timestep. Avoid automatic 1km as accuracy choice.
  4. Test reduced atmosphere with actual wind circulation, thermal feedback and terrain-driven rain, high/low pressure/frontal propagation, local storm footprint and offscreen refinement, independent reference. Include soil/groundwater, sediment, liquid families, cold phase and heat closure. Provisional reduced geometry and accounting probes support the test, not production.
  5. Test actual volumetric Godot renderer and moving sun/camera against user art reference; include full GPU frame and VRAM. Prove native multi-layer route construction and dynamic edits with HPA-style local paths, shared destinations, real 1k/10k/100k mixed agents and ECS. No benchmark substitution.
  6. Integrate bounded playable slice; then 100x100km storm, 4,000km macro and 800km route with increasing simultaneous active areas, save/reload, measured complete CPU/GPU/RAM/debt. If failure, stop at the discriminating issue; no new blanket framework.
