Environmental Foundation V1 — fast environmental development and continuous terrain LOD

27 November 2026. User-approved active execution plan. This supersedes prior scene-first, colony-based, and mandatory showcase interpretations. Previous exact delivery plan. The technical plan remains the selected numerical and architectural baseline; execution protocol governs delivery. No new implementation or performance claim is made by this authorization.

Binding scope and authority

One permanent, reusable environment-only development baseline for Codex, not a user-facing application. Native C++/headless execution is preferred for numerical work when cheaper; use the same underlying V1 owners and at most one active Godot environmental development scene for rendering, streaming and integration. UI is optional and not a deliverable. Reuse existing code and artifacts, never create a new scene or simulation for each test. No colonist creation, ticks, walking, scheduling, navigation/settlement work, benchmarking, optimization or compatibility work in this scope. Colonists will be revisited separately; preserve existing unrelated source and saves, not their current implementation as a requirement.

The user and planning chat own substantive architecture decisions through the canonical Brain. Codex follows the selected stack, requirements and contracts; it may make bounded implementation fixes, dependency-aware build changes, safe caches and reversible configuration choices within that design. Do not reopen solver/renderer selection, replace Zylann, change authoritative ownership, physical clocks, requirements, major dependencies, or scope without explicit user approval. Report an evidenced fundamental blocker and a concrete recommendation; continue independent in-scope work.

Retain GeoGenesis, selected PWG methods, Zylann, Wflow-derived water and groundwater, NOAA CFE, FluxCell, MeanderPy, Weather3D-derived circulation, CliMA phase physics, COARE-derived exchange and SunshineClouds2 as selected in the technical plan. Keep independent spatial/temporal granularity, 1:1 coupled physical clock, finite water/heat/sediment custody, current editable geometry, offscreen consequences, and attractive eventually scalable rendering. No second production solver or terrain authority. No forced backward compatibility with obsolete colony, save or environment mechanisms. Environmental field/geometry query contracts remain; do not implement or qualify their colony consumers now.

B. Terrain loading and smooth continent-to-ground rendering — priority after A

Achieve this with minimal architectural change and existing Zylann/Transvoxel functionality wherever feasible. A whole-continent 2D atlas or logical world size alone is not proof of this 3D requirement.

  1. On the same reusable high-relief/channel-bearing location, measure cold/warm first coarse visible terrain, first usable local detail, convergence and rapid zoom/flyover. Separate formation/export, recipe/hydrography admission, generator work, stream/mesh/transfer/main thread/collision and GPU costs. Use existing counters and timing, selected near/mid/far material and LOD/wireframe captures, intermediate frames and visible readiness; do not assume a cause from source alone. The earlier continent-style lab had six LODs, local 1,024m view and a separate macro chart, not continuous whole-domain 3D. Reuse relevant existing code only; do not revive its old geography authority.
  2. Fix dominant measured generation/streaming bottlenecks in a coherent batch. Evaluate uniform air/solid fast paths, repeated X/Z work across vertical blocks, allocation/copy and bounded caches only where profile supports them. Preserve SDF/material semantics, cave/overhangs, edits, borders and actual hydraulic geometry. Reuse upstream controls. Tune configurable LOD count, distance/error, transition/fade, cache/GPU options, collision and viewer demand according to actual measurements; do not blindly raise global draw distance or fine voxel count.
  3. Keep a usable coarser representation resident until required finer coverage is ready; prioritize destination refinement, bound/cancel stale requests where supported, avoid visible holes, cracks, popping, z-fighting and large transient allocations. Use existing world-coordinate/rebase conventions for large distances. Keep collision and fine generation local or physically requested, not continent-wide. Camera only controls presentation; simulation and physical state remain independent.
  4. If measured existing Zylann coverage is inadequate at continent/mid-scale, use the cheapest necessary derived coarse surface/mesh hierarchy from the same current recipe plus revisioned edit/morphology summaries. Reuse existing raster/mesh/paging pieces when suitable. Select detail by projected error/coverage; use bounded residency and localized invalidation; preserve shared coast/river/landform placement and continuity when handing off to near Zylann meshes. This is a conditional small presentation adapter, not a second solid world, new renderer project, SVDAG migration or solver redesign. If it requires a fundamental renderer or ownership change, report blocker for user decision before proceeding with that change.
  5. Verify one normal near/mid/far sequence and a cached continent-scale zoom at meaningful terrain acceptance, not every subsequent package. Show actual Godot 3D, stable coverage and transitions, bounded working-set/queue costs, current edits agreeing with near and relevant coarse data, and measured first-visible/usable latency and frame/memory costs. Compare like-for-like against the initial baseline. Do not invent a fixed timing target absent agreement; improve demonstrated major bottlenecks and report remaining defects. Keep eventually attractive shading, geology and recognizable terrain; no camera-driven changes to physical state. A 2D atlas remains a cheap independent diagnostic.
